# Руководство По Репозиторию

## Коммиты

- Используйте **Conventional Commits** для всех коммитов: `<type>(<scope>): <subject>`.
- Типы: `feat` (новая фича), `fix` (исправление бага), `docs`, `style`, `refactor`, `test`, `chore`.
- Scope — опциональный, описывает секцию кодовой базы (компонент, сервис, подсистему).
- Примеры: `feat(bookings): add conflict detection`, `fix: handle nil slot on expiry`, `chore: update deps`.

## Проверка Изменений

- Один раз выполните `task setup`, чтобы установить закреплённые инструменты Go в `bin/` и зависимости TypeSpec через `npm ci`.
- Перед коммитом запускайте ту же последовательность, что и `task ci`: `task check:api`, `task vet`, `task lint`, затем `task test`. `task test` выполняет `go test -v -race -count=1 ./...`.
- Для выборочных Go-тестов сохраняйте race detector и отключайте кеширование, например: `go test -race -count=1 ./internal/usecase -run '^TestBookingUsecase_'`.
- Для изменений Go используйте `task format`. Команда применяет `gofumpt -extra` и группировку импортов `gci`; `task lint` также проверяет оба форматтера и правила golangci-lint.
- Перед коммитом сверьте `git diff` с картой из раздела «Документация» и обновите все затронутые MD — документация поддерживается так же, как код.

## API-Контракт

- Считайте `api/*.tsp` и `api/routes/*.tsp` источником истины для REST API. При изменении контракта перегенерируйте коммитируемый `api/generated/openapi.yaml` командой `task gen:api`, затем внесите соответствующие изменения HTTP-слоя.
- `task check:api` перегенерирует спецификацию и завершится с ошибкой, если `api/generated/openapi.yaml` устарел; CI выполняет эту проверку отдельно.

## Документация

- Markdown-файлы (`README.md`, `docs/*.md`, `.github/workflows/README.md`, `AGENTS.md`) — такая же часть кодовой базы, как и код: устаревшая документация — это баг. Любое изменение поведения, контракта, конфигурации или workflow обязано обновлять затронутые MD **в том же коммите**.
- Карта соответствий «что меняешь → что обновляешь»:
  - поведение и эндпоинты → `README.md` (таблица API) + `docs/PRD.md`;
  - слои и структура → `docs/ARCHITECTURE.md`;
  - тестовые сценарии → `docs/TESTING.md`;
  - дорожная карта и статус → `docs/TODO.md`;
  - термины и определения → `docs/CONTEXT.md`;
  - UI и визуальный язык → `docs/DESIGN.md`;
  - CI и OpenCode-workflow'ы → раздел «ИИ-агенты» в `README.md` + `.github/workflows/README.md`;
  - конвенции для агентов → `AGENTS.md`.
- Если правка меняет описанный в MD факт (путь, флаг workflow, команду Taskfile, эндпоинт, ключ конфига), обновляйте его дословно, а не «примерно».
- Перед коммитом сверьте `git diff` с этой картой и убедитесь, что ни один затронутый документ не остался устаревшим.

## Структура

- `cmd/server/main.go` является корнем композиции: здесь связываются конфигурация, SQLite, репозитории, use cases, роутер, статические файлы и graceful shutdown.
- Зависимости должны быть направлены внутрь: `internal/domain` не зависит от фреймворков и хранилищ; `internal/usecase` содержит бизнес-логику и порты репозиториев в `internal/usecase/repository`; реализации SQLite находятся в `internal/infrastructure/sqlite`; HTTP-адаптеры находятся в `internal/interfaces/http`.
- SPA не использует фреймворк. Go-сервер отдаёт `web/index.html`, а его API-клиент расположен в `web/js/api.js`.
- Контекст и детали: `docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/DESIGN.md`, `docs/TESTING.md`, `docs/TODO.md`.

## Запуск И Данные

- Запускайте из корня репозитория: `task run` читает `config.yaml`, отдаёт `web/` и по умолчанию использует `data/calendar.db`. Сервер слушает порт из `config.yaml` (по умолчанию 8080). Переопределяйте значения через `CONFIG_PATH`, `STATIC_DIR`, `DB_PATH` и `PORT`; `PORT` должен быть целым числом от 1 до 65535 и имеет приоритет над `config.yaml`.
- Конфигурация включает in-memory `rate_limit` (30 запросов/мин, burst 10 — ожидайте 429 при превышении), привязку админки `admin.owner_uuid` и healthcheck на `GET /healthz`.
- Для запуска в Docker: `task docker:build` собирает образ, `task docker:run` запускает контейнер с volume для базы (порт из `PORT`, по умолчанию 8080).
- Миграция схемы SQLite и идемпотентные seed-данные выполняются при запуске сервера. База по умолчанию игнорируется Git и сохраняется между локальными запусками, поэтому для чистого ручного состояния используйте отдельный `DB_PATH`.
- SQLite намеренно рассчитан на один экземпляр: одно открытое соединение, WAL, внешние ключи, немедленные транзакции записи и busy timeout защищают создание бронирований. Не меняйте эти настройки без сохранения поведения при конкурентном доступе.
- Это учебное демо без аутентификации; административные эндпоинты раскрывают email гостей. Не развёртывайте его в публичной или общей сети и не используйте реальные персональные данные.
